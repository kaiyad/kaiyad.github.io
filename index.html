NAME

Kailash Yadav kailash — software engineer; builds durable, event-driven systems and the tools that keep them honest

SYNOPSIS

kailash [-l python|go|typescript] [-i kubernetes|docker|helm]
        [-d distributed-systems|workflow|storage|networking|hardware]
        [-v] <problem>

kailash --ship [--from-scratch] [--on-call] <product>

DESCRIPTION

kailash takes a system that has to keep its promises while things fail underneath it, and makes it do that. Eight years of it: first validating the server hardware that cloud regions are built from, then the control planes that orchestrate storage and recover from failure, and now the workflow engine that drives cloud-savings automation at IBM Apptio Cloudability.

The common thread is durable execution — state that survives a restart, retries that are safe to run twice, and a log you can read afterwards to find out what actually happened. Started close to the metal, which is why the distributed parts don't feel like magic.

Off the clock, kailash ships developer tools: a drill CLI that quizzes you on your own code, a daily digest that is immutable by database trigger, and a catalogue of engineering practices for teams where most of the code is now written by a model.

OPTIONS

-l, --lang lang
Python for anything that has to be readable a year later. Go when it should be one binary with no runtime. TypeScript when there is a UI attached. C and shell when the machine insists.
-d, --domain domain
Workflow orchestration and durable execution, distributed systems, object storage, networking, BMC and server hardware, developer tooling.
-i, --infra target
Kubernetes (Helm, StatefulSets, operators), Docker, Postgres, SQLite, REST and event-driven interfaces, DMTF Redfish for anything with a baseboard management controller.
--ship
Takes a thing to production rather than to a demo: migrations, rollout, dashboards, the pager rotation, and the postmortem when it still goes wrong.
-v, --verbose
Will explain why at-least-once delivery is fine, or the rope data structure behind Edituh, entirely unprompted. Repeat for diagrams.

EXAMPLES

Things built outside work hours, each one because a tool I wanted didn't exist.

Keep your own code in your head sharp drill

A local CLI that picks a function you wrote, blanks its body or plants a one-token bug in it, and makes you put it back with no AI and no autocomplete — then tracks whether you're getting faster. A card is only offered if your test suite actually catches the edit, so every drill has a real pass/fail oracle. No server, no account, no network call: all state is one SQLite file.

github.com/kaiyad/sharp
TypeScript node:sqlite CLI
Engineering practices for when the model writes the code ctxc build && i2e run --gate

Twenty-eight proposed practices for teams where most code is written by a model, held as data so the tools and the docs can't drift apart — and working first versions of the four that change the delivery pipeline most: ctxc compiles decision records, incidents and rules into a versioned context artifact and lints it; i2e turns every postmortem into a permanent eval case that gates prompt and model changes; friction charges agent stalls and thrash to the module that caused them; tier derives how much autonomy a change is allowed from its blast radius. Local, zero-dependency Node.

github.com/kaiyad/keel
TypeScript Agent tooling Evals
One frozen edition of software news a day npm run daily

A dated daily digest collated from Hacker News, Lobsters, GitHub, arXiv, Reddit and ~90 engineering blogs and changelogs — 19 ranked entries plus a hand-written curriculum unit, about a fifteen-minute read. An edition is frozen when it publishes and never changes again, enforced by Postgres triggers rather than by application code, because a feed that keeps backfilling has no stable yesterday.

A documentation workspace that works offline edituh --desktop

A Confluence/Notion-style documentation editor for web and desktop: math, diagrams, bidirectional links, a knowledge graph and daily notes, on a balanced rope so large documents stay fast to edit. FastAPI and React (BlockNote, Mantine), shipping as desktop installers and a PWA.

Make every engineer's agent follow the same process cp -r skills/ ~/.claude/skills/

A small, composable set of development skills for AI coding agents, built to reduce variance rather than to automate thinking away. The organising principle is that a skill guides and does not enforce, so anything mandatory belongs in CI and the skills cover the judgment-heavy process CI can't check — spec, design, pre-mortem, implement, test, review, ship.

BUGS

  • Reaches for a distributed primitive before asking whether one process would have done. Aware of it; still does it.
  • Will rewrite your build tooling if left unattended for a sprint.
  • Wants the first version to be right, which costs more than shipping the second version would have. Mitigated, not fixed.
  • Cannot leave a manual page unread, including this one.
